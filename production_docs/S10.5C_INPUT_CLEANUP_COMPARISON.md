## 1. Executive Summary & Objective

Stage S10.5C evaluated whether Gemini image cleanup/regeneration meaningfully improves OpenCV profile tracing by comparing three real input routes using manual QA technical drawing profiles from `samples/manual_qa/`:

1. **Route 1:** Dimensioned technical drawing (`samples/manual_qa/interface_b_original.jpg`) directly into current OpenCV cleanup & tracing.
2. **Route 2:** Dimensioned technical drawing (`samples/manual_qa/interface_b_original.jpg`) passed to Gemini image generation with the exact cleanup prompt:
   > *"Regenerate this image without dimensions, text, arrows, leader lines, or center marks. Show only the exact grey cross-section on a plain white background. Preserve every edge, slot, curve, hole, cavity, and proportion exactly. Do not simplify or redesign the profile."*  
   Followed by OpenCV tracing on the regenerated image.
3. **Route 3:** Dimension-free clean shaded profile (`samples/manual_qa/interface_a_original.jpg`) directly into OpenCV cleanup & tracing.

## 3. Deep-Dive Findings per Route

### 3.1 Route 1: Dimensioned Image Directly (`interface_b_original.jpg`) — RESULT: FAIL
- **Behavior:** Standard OpenCV thresholding (`cleanup_image_v2`) converts all black pixels (drawing outlines + dimension lines + text) into white foreground mask pixels.
- **Defects:**
  1. Dimension extension lines touching the profile outer edge cause `cv2.findContours` to expand the outer envelope to include text boxes ("40", "11", "20").
  2. Leader lines and dimension arrows create 10 spurious inner/outer noise contours.
  3. Physical T-slot geometry is obscured wherever dimension lines intersect the boundary.

### 3.2 Route 2: Dimensioned Image after Gemini Cleanup — RESULT: FAIL
- **Behavior:** Gemini image generation stripped all text, numbers, arrows, and leader lines, outputting a clean shaded cross-section.
- **Defects:**
  1. **Hallucinated / Altered Geometry:** Gemini altered structural cross-section features. Flat, 90° T-slot flange lips were morphed into diagonal triangular arrowhead shapes.
  2. **Proportional Distortion:** Web angles and wall thicknesses were slightly shifted, causing OpenCV's extracted contour to fail alignment against the original technical drawing (`interface_b_original.jpg`).
  3. **Violation of Result Rules:** Stage S10.5C result rules explicitly state: `FAIL if Gemini changes or invents geometry`. Therefore, generative AI image-to-image cleanup is rejected for production use.

### 3.3 Route 3: Already-Clean Shaded Profile (`interface_a_original.jpg`) — RESULT: PASS
- **Behavior:** OpenCV preprocessing and contour extraction operated directly on the dimension-free shaded cross-section image.
- **Results:**
  1. Extracted exact 44-vertex non-convex outer boundary with complete T-slot recess preservation.
  2. Identified all 9 enclosed inner regions (central bore Ø6.8 mm, T-slot pockets, screw holes).
  3. Produced zero noise contours and achieved 100% visual overlay alignment against the source drawing.

---

## 4. Production Pipeline Recommendation

### Recommended Production Architecture:
1. **DO NOT use generative AI image-to-image cleanup** (Route 2) as a geometry preprocessing step. LLMs/Diffusion models cannot guarantee pixel-level edge preservation for CAD profiles.
2. **DO NOT pass raw dimensioned line drawings directly into OpenCV thresholding** (Route 1) without ROI masking.
3. **PRODUCTION ROUTE (Hybrid Masking & Tracing):**
   - Use Gemini Multimodal Vision solely for **Bounding Box Detection & Annotation Region Masking** (bounding boxes `[ymin, xmin, ymax, xmax]`), which is used by `cleanup_image_v2` to zero out annotation pixels deterministically.
   - For unshaded CAD line drawings with dimensions, use Gemini's structural annotation bounding boxes to perform targeted OpenCV box-masking before contour extraction.
   - For clean/shaded profile uploads, execute direct OpenCV pixel contour extraction (Route 3).
