## 1. Executive Summary & Objective

Stage S10.5H productionizes the upload guidance and input requirements across both Interface A and Interface B upload screens.

The objective is to stop treating heavily annotated technical drawings as the preferred input, and to update all product messaging, UI, documentation, and tests to reflect the actual reliable input standard: a clean, dimension-free cross-section image.

The annotation masking path (S10.5G) remains available as an **experimental / manual review required** capability — it is explicitly not presented as production-ready or automatic.

## 3. Product Messaging Summary

### What the product now says

> For best results, upload a clean cross-section image without dimensions or annotations. One confirmed measurement is enough to scale the profile accurately.

> Dimensioned drawings may introduce false edges and require manual cleanup.

### What the product no longer says (removed/never existed)

- "Arbitrary technical drawings are always supported" — ✗ Not present
- "Annotation masking is production-ready" — ✗ Replaced with "Experimental / manual review required"
- "Gemini cleanup preserves CAD geometry perfectly" — ✗ Not present
- "Heavily dimensioned drawings are the recommended path" — ✗ Not present; dimensioned drawings listed as NOT recommended

## 4. Annotation Drawing Support Status

**Status: Experimental / manual review required**

- Annotation masking (S10.5G/S10.5G.1) is available as a pipeline pre-step
- It reduces annotation noise but does not eliminate all false edges at junction points
- Users who upload dimensioned drawings see `⚠ Manual cleanup likely` quality badge
- The traced SVG profile must be reviewed and corrected manually before approval
- This path is not removed; it is reframed as an experimental option

---

## 5. Scale Workflow

```
User uploads clean cross-section
→ Backend traces profile (OpenCV)
→ User enters optional known measurement in guidance panel
→ Profile review and SVG editing
→ User confirms scale measurement (mandatory gate)
→ Scale applied
→ Profile approved
→ 3D generation begins
```

Scale is **never applied automatically**. The confirmation gate is enforced at the profile approval step (ADR-004, `scale_calibration.confirmed == true` required for `traced_closed` profiles).

## 9. Governance

### Conflicts Between Source Documents
None identified. S10.5H is additive guidance — it does not change the canonical schema, user flow sequence, or geometry scope.

### Missing Information
- The heuristic quality classifier uses filename signals only. A pixel-level classifier would be more accurate but is post-MVP scope.
- The `known_measurement` field in the upload payload is defined in API_USAGE.md but not yet wired to the backend upload endpoint. Scale calibration currently flows through the profile PATCH endpoint (`scale_calibration` field). This is consistent with existing behaviour.

### Risks
- If the heuristic classifier misclassifies a dimensioned drawing as "Usable with review" instead of "Manual cleanup likely", the user may proceed without adequate warning. The backend GeminiAnalysisProvider is the authoritative quality gate.

### Technical Debt
- Pixel-level quality classification is a future improvement.
- The SVG placeholder illustrations are static SVG elements. Real example screenshots would be more informative.
