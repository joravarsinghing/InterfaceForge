# Stage S10.8 - Top Step Navigation State Restore

**Stage Status:** Complete  
**Date:** July 29, 2026  
**Scope:** Correct top-step navigation for revisiting Interface A and Interface B without resetting saved interface state.

## Problem

Top workflow navigation linked Interface A and Interface B directly to their upload routes. After a user uploaded, reviewed, or approved an interface and progressed further, clicking the completed interface step could show the upload page again even though backend project state still contained the saved source image, trace, dimensions, warnings, scale data, and approval status.

## Fix

Added a shared frontend route resolver in `frontend/src/services/workflow.ts`:

- no saved interface source and no approval routes to upload;
- uploaded but unapproved routes to profile review;
- approved routes to profile review/summary;
- both Interface A and Interface B use the same logic.

`StepNavigation` now uses this resolver for Interface A and Interface B links. `UploadPage` also redirects to the resolved review route if a user reaches an upload URL for an interface that already has saved state.

## Governance

No canonical schema, backend API responsibilities, geometry scope, approval gates, upload behavior, analysis behavior, generation behavior, export behavior, or Agent behavior were changed.

## Risks

Directly entering `/step1` or `/step2` now preserves existing interface state by redirecting to review when project state has a saved image or approval. Forward-step locking remains governed by `ProtectedRoute` and `getEarliestIncompleteStep`.
