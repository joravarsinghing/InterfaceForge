## 1. Executive Summary & Pipeline Overview

Stage S10.5B builds upon the pixel-derived OpenCV profile contours from S10.5A by establishing:
1. **Confirmed Millimetre Scale Calibration:** Mandates explicit user confirmation of reference dimensions before manufacturing-ready profile approval can occur.
2. **Geometry-Linked Editable Dimensions:** Connects extracted and user-edited parameters directly to the 2D polygon vertices (`traced_outer_contour` and `traced_hole_contours`), ensuring that editing a parameter updates the physical vector geometry.
3. **Consistency & Conflict Detection:** Cross-validates mapped dimensions against pixel geometry scale; flags discrepancy beyond 5% tolerance as a `conflict` state with explanatory warnings.

```text
Original Drawing Image
  │
  ▼
Gemini Vision Extraction
  ├─ Reads visible text annotations & dimensions
  └─ Maps dimension parameters to SVG features (outer_contour, region_1, etc.)
  │
  ▼
Scale Calibration Confirmation Gate
  ├─ User confirms reference dimension (e.g. overall_width = 40.0 mm)
  └─ Converts pixels to mm units; validates other mapped dimensions
  │
  ▼
Geometry-Linked Dimension Editing
  ├─ User edits supported parameter (e.g. bore_diameter 6mm -> 12mm)
  ├─ Deterministic polygon transformation recalculates contour vertices
  ├─ Self-intersection check ensures geometric integrity
  └─ Dynamically regenerates SVG trace & real source image overlay
```

## 2. Scale Confirmation Evidence

- **Mandatory Approval Gate:** Profile approval endpoint (`POST /api/projects/{pid}/interfaces/{id}/approve`) strictly rejects approval requests if `scale_calibration.confirmed` is `False`, returning a `400 Bad Request` with message: `"Cannot approve interface: Scale calibration must be confirmed."`.
- **Reference Calibration:** Scale calibration maps pixel dimensions to real mm units (e.g., 400 pixels = 40.0 mm, yielding $0.1 \text{ mm/px}$).
- **Cross-Validation:** Mapped dimensions are validated against physical contour bounding boxes. Discrepancies exceeding 5% tolerance are set to `consistency_state = "conflict"`.

## 3. Dimension Mapping Evidence

Every extracted or user-defined dimension includes the following 7 mandatory metadata attributes:
- `value` (e.g., `40.0`) and `unit` (`"mm"`)
- `feature_ref` (e.g., `"outer_contour"`, `"region_1"`)
- `source_annotation` (e.g., `"40"`, `"Ø6.8"`, `"R5"`)
- `provenance` (`"image_extracted"`, `"user_entered"`, `"system_inferred"`, `"unresolved"`)
- `confidence` (e.g., `0.95`)
- `critical` (`True` / `False` fit-critical status)
- `consistency_state` (`"valid"`, `"conflict"`, `"unmapped"`, `"recalculated"`)

### Unmapped Annotation Handling
Annotations detected in drawing text that cannot be safely mapped to a specific CAD geometric feature are explicitly labeled:
`"Detected annotation — not mapped to geometry"` with `consistency_state = "unmapped"`.

## 4. Editing Proof & Geometry Update Mechanism

Supported dimension edits deterministically transform 2D polygon vertices:

| Supported Dimension | Geometry Transformation | Recalculation Behavior |
| :--- | :--- | :--- |
| **Overall Width** | Scales X-coordinates of outer & hole contours: $x_{\text{new}} = x \times (W_{\text{new}} / W_{\text{curr}})$ | `consistency_state = "recalculated"` |
| **Overall Height** | Scales Y-coordinates of outer & hole contours: $y_{\text{new}} = y \times (H_{\text{new}} / H_{\text{curr}})$ | `consistency_state = "recalculated"` |
| **Hole / Bore Diameter** | Scales target hole contour vertices relative to centroid: $r_{\text{new}} = D_{\text{new}} / 2$ | `consistency_state = "recalculated"` |
| **Hole Center X / Y** | Shifts target hole contour vertices: $\Delta x = X_{\text{new}} - X_{\text{curr}}$, $\Delta y = Y_{\text{new}} - Y_{\text{curr}}$ | `consistency_state = "recalculated"` |
| **Hole Spacing** | Adjusts relative displacement between symmetric hole centroids | `consistency_state = "recalculated"` |
| **Slot Width / Depth** | Scales slot contour notch vertices along slot axis | `consistency_state = "recalculated"` |
| **Inner Region Decision** | Toggles region state between `include`, `ignore`, `unsure` | Updates SVG layer rendering & hole list |

### Reversion & Inconsistency Prevention
If a user edit causes polygon self-intersection or non-finite coordinates:
1. The geometry transformation is immediately reverted to the last-known-good state.
2. The dimension state is set to `consistency_state = "conflict"`.
3. An inconsistency warning is issued to the user: `"Geometry edit resulted in self-intersecting polygon. Reverted to previous geometry."`. Text values are never silently mutated without updating geometry.

## 5. UI Step-by-Step Guided Workflow

The Profile Review interface (`frontend/src/pages/ProfileReviewPage.tsx`) guides the user through 5 sequential steps:
1. **Confirm Scale:** Interactive Scale Calibration panel to confirm reference dimension & real mm distance.
2. **Review Openings:** Internal Cavities table listing enclosed negative regions with `include`, `ignore`, `unsure` toggles.
3. **Review Fit-Critical Dimensions:** Fit-critical badges (`critical = True`) and consistency state indicators (`valid`, `conflict`, `recalculated`, `unmapped`).
4. **Edit Geometry-Linked Values:** Interactive dimension inputs that instantly update 2D polygon points and SVG previews.
5. **Approve Profile:** Prominent approval button, enabled only when scale is confirmed and fit-critical dimensions are valid.
