## 1. Executive Summary & Pipeline Overview

Stage S10.5A replaces direct Gemini-authored 2D polygons with a deterministic, hybrid AI/computer-vision profile tracing pipeline:

```text
Original Drawing Image
  │
  ▼
Gemini Multimodal Vision Model
  ├─ Identifies crop bounding box (ROI around cross-section)
  ├─ Identifies annotation regions (dimension text, arrows, leaders, centerlines to mask)
  ├─ Extracts scale calibration (mm per pixel)
  └─ Provides cleanup guidance (threshold method, invert, blur kernel)
  │
  ▼
Deterministic Image Cleanup V2 (`cleanup_image_v2`)
  ├─ Crops ROI
  ├─ Masks out annotation text & arrow boxes with background pixels
  └─ Applies Gaussian blur, Otsu thresholding, and morphological closing
  │
  ▼
OpenCV Profile Tracer (`extract_pixel_contours`)
  ├─ Finds non-convex outer contour perimeter
  ├─ Extracts enclosed inner hole contours (central bore, T-slots, screw holes)
  ├─ Computes contour hierarchy (parent-child relationships)
  └─ Simplifies pixel jitter via Ramer-Douglas-Peucker (`approxPolyDP`)
  │
  ▼
SVG Trace & Real Source Overlay Generation (`generate_svg_trace_and_overlay`)
  ├─ Clean vector SVG trace (`artifacts/trace_<id>.svg`)
  └─ Real source image overlay (`artifacts/overlay_<id>.svg`) embedding original drawing
```

### Correction of Earlier Documentation Claims
Earlier stage reports (S10.4 and S10.4A) described Gemini vision responses as exact geometric traces. In S10.5A, we explicitly clarify and correct that statement: **Gemini is restricted to image guidance, ROI cropping, annotation identification, and scale calibration. All final 2D contour coordinates, raw and simplified point sets, hierarchy relationships, and vector overlay paths are generated deterministically by OpenCV from real image pixels.**

## 3. UI Requirements Verification

For traced profiles on the Profile Review page (`frontend/src/pages/ProfileReviewPage.tsx`), the interface renders four view mode tabs:
1. `📷 Original`: Original uploaded drawing image
2. `🧹 Cleaned Image`: Deterministic cleanup image V2 artifact
3. `✏️ Trace`: Clean standalone vector SVG trace
4. `🔀 Overlay` (**Default!**): Real source image overlay combining drawing image & vector trace

### Visual Feature Distinction & Color Coding:
- **Outer boundary:** Solid cyan/green line (`#00e5ff` / `#10B981`)
- **Included opening:** Solid green/cyan line (`#00e676` / `#06B6D4`)
- **Ignored region:** Dashed orange/gray line (`#ff9100` / `#6B7280`)
- **Uncertain contour:** Dashed purple/amber line (`#d500f9` / `#F59E0B`)

**Approval Gate:** Traced profiles start in `opencv_traced_pending_review` status. The "Verified" badge is never displayed before explicit user approval.

## 4. Validation Rules & Self-Audit Results

1. **Bounding-Box Rejection:** Complex profiles returning 4-point bounding boxes are flagged and rejected with warning: `"Profile flagged complex requires detailed non-convex perimeter; 4-point bounding box is a simplified envelope."`
2. **Self-Intersection Prevention:** Polygon self-intersections are detected via segment intersection checks and rejected.
3. **Single Focused Retry:** If initial cleanup fails or produces self-intersection, 1 focused cleanup retry with adjusted parameters is attempted. If retry also fails, failure is reported honestly.
4. **Primitive Profile Regression:** Primitive shapes (circle, rectangle, rounded rectangle) remain 100% operational.
