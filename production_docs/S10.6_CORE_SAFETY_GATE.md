﻿# Stage S10.6 - Core Safety Gate

**Stage Status:** Complete  
**Date:** July 28, 2026  
**Scope:** Submission-critical profile workflow reliability only.

## Summary

This stage tightened the upload-to-review measurement path, explicit scale confirmation, profile approval safety, contour-validation complexity bounds, and last-known-good preservation behavior.

## Changes

- Upload can carry one known measurement for `overall_width`, `overall_height`, `hole_diameter`, or `reference_distance` in millimetres.
- The measurement is stored using existing canonical `Dimension` and `ScaleCalibration` fields; no schema-version change was introduced.
- Analysis hydration preserves the upload measurement and keeps scale unconfirmed until the user explicitly confirms it.
- Backend approval rejects unconfirmed calibration, missing traced profile data, open contours, self-intersections, unresolved severe validation errors, and direct PATCH approval bypasses.
- Contour self-intersection checks now enforce a 2,000 point contour cap and 250,000 segment-comparison budget with `IF-PROFILE-COMPLEXITY-BUDGET` diagnostics.
- Severe invalid updates to an approved profile are rejected without overwriting the last approved traced geometry; generation failures preserve `current_model_revision` and `last_known_good_model_revision`.
