## Root Cause

**Exact component/function:** `handleUploadAndAnalyze` in
`frontend/src/pages/UploadPage.tsx` (line 78)

**Why the page reset:**

After `analyzeInterfaceImage` returned 200 OK, the handler called
`navigate('/step1/analysis')` immediately.
`ProtectedRoute` at `/step1/analysis` evaluates
`getEarliestIncompleteStep(project)` using the **stale in-memory `project`**
prop that still had `interface_a.source_image_ref = null` (the value it held
before the upload/analyze sequence). The workflow service therefore returned
`/step1` (STEP_ORDER = 1) as the earliest incomplete step, which is less than
`/step1/analysis` (STEP_ORDER = 2), so `ProtectedRoute` issued a
`<Navigate to="/step1" replace />` redirect — silently sending the user back
to the upload screen on every attempt.

**No backend defect was found.**
The analyze endpoint correctly:
- set `project.state = WorkflowState.INTERFACE_A_REVIEW_REQUIRED`
- set `target_interface.source_image_ref` (written during the prior upload call)
- saved the updated project to the repository

The frontend simply never read the updated project back before navigating.

---

## Fix (3 bullets)

1. **`UploadPage.tsx` — refresh project after analyze:**
   After `analyzeInterfaceImage` resolves, call `fetchProject(project_id, token)`
   to obtain the backend's persisted state (which has `source_image_ref` set and
   `state = interface_a_review_required`). If the refresh fails, show an inline
   error and keep the selected image — do not silently reset.

2. **`UploadPage.tsx` — new `onProjectUpdate` prop:**
   Call `onProjectUpdate(refreshedProject)` before `navigate(...)` so that
   `App.tsx` writes the fresh project into React state before the route guard
   evaluates it. Navigation fires only after state is propagated.

3. **`App.tsx` — wire `onProjectUpdate` to both `UploadPage` instances:**
   Both `/step1` and `/step2` routes now pass
   `onProjectUpdate={(updated) => setProject(updated)}` so the fix applies
   symmetrically for Interface B as well.

**Bonus hardening:** The Analyze button is disabled (`disabled={loading}`) while
any async operation is in progress, preventing duplicate requests.
