## 1. Root Cause Summary

The previous S10.5G "PASS" was incorrect. The actual pipeline in `cleanup_image_v2` contained **five compounding coordinate bugs**:

| Bug | Description | Effect |
|-----|-------------|--------|
| **Bug 1** | `crop_box` assumed 0–1 normalized; Gemini returns 0–1000 integers | Crop region 1000× too large — cut or filled entire image |
| **Bug 2** | Annotation boxes applied **after** 2× upscale using `[ay1*ch, ax1*cw]` — `ch/cw` already included the scale factor | Boxes positioned 2× further into image than intended |
| **Bug 3** | No validation that crop proposal didn't cut the real profile extent | Valid geometry silently removed by bad crop |
| **Bug 4** | Protected geometry check used filled profile body — thin dimension lines inside profile bbox rejected | 6/9 Gemini annotation regions wrongly rejected |
| **Bug 5** | Annotation masking applied in upscaled crop space, not original image space | Coordinate offset drift introduced by crop |

## 2. Gemini Coordinate Format Proven

**Live request evidence (`02_gemini_raw_response.json`):**

- **Provider:** `gemini`
- **Model:** `gemini-3.5-flash-lite`
- **Request ID:** `req_gemini_<timestamp>`
- **Coordinate format:** Normalized 0–1000 integers, order `[ymin, xmin, ymax, xmax]`
- **Region count:** 8–9 (varies per live call)
- **Fallback used:** `False`

Example raw crop box: `[22, 140, 955, 857]` → pixel box: `[18px, 110px, 764px, 672px]`  
Image is `784×800px`. Protected profile extent: `y=48..752, x=63..695`.  
`x2=672 < protected_right=695+15=710` → **CROP REJECTED** → full image used.

## 3. Fixes Implemented

### 3.1 `backend/app/services/coordinate_normalizer.py` (new module)

| Component | Description |
|-----------|-------------|
| `normalize_box()` | Detects 0–1 / 0–1000 / absolute-pixel format automatically. Enforces `ymin<ymax` swap. Clips to image bounds. Asserts positive width/height. |
| `build_protected_geometry_mask()` | 5×5 morphological opening + 8px erosion to isolate **thick solid profile walls only** — excludes dimension lines from protected set |
| `validate_crop_box()` | Ensures crop proposal fully contains protected profile extent + 15px margin; rejects and falls back to full image otherwise |
| `safer_annotation_masking()` | Full pipeline: EXIF fix → protected mask → crop validation → per-region normalized box → erosion-overlap check → white-fill → 3×3 morph close for edge repair |

### 3.2 `backend/app/services/opencv_tracer.py`

- `cleanup_image_v2` now delegates all masking/crop logic to `safer_annotation_masking`
- Annotation pixels are removed **before** crop and **before** upscale — correct order
- EXIF orientation stub integrated

### 3.3 `backend/app/models/schema.py`

Diagnostic fields added to `AnalysisResult`:
- `provider_used: Optional[str]`
- `request_id: Optional[str]`
- `fallback_used: bool = False`
- `region_count: Optional[int]`

### 3.4 `backend/app/services/analysis_provider.py`

`GeminiAnalysisProvider.analyze()` now populates all four diagnostic fields on successful result.
